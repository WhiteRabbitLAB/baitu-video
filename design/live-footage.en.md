# Live-action footage in the picture (existing public-domain / licensed footage)

【Capability boundary updated 2026-10-10】The engine originally only drew code animation. Existing live footage (not filmed by us) can be wired into the same page this way, sharing layers, transitions, subtitles and the chapter bar with the animation. Proven on a 13-minute full video.

## Where footage comes from, what to accept
| Source | License | How | Notes |
|---|---|---|---|
| Government public-domain video (e.g. US national park video libraries, NASA, USDA) | Public domain | mp4 links on the page | Often 720p only; each page states the filming location — **use it to verify what the shot shows** |
| Wikimedia Commons | Accept public domain / CC0 / CC BY only; **reject CC BY-SA** (it would propagate to the film) | `api.php?list=search&srsearch=<term> filetype:video` + `prop=imageinfo&iiextmetadatafilter=LicenseShortName\|Artist` gets license and author in one call | Parallel downloads get 429: **download one at a time, 2–3 s apart, with a User-Agent that has contact info**; CC BY needs attribution in the description |
| Pexels | Pexels license (commercial use, no attribution) | The search page blocks curl but WebFetch can read IDs; download via `pexels.com/download/video/<id>/` | Many are vertical; a place name in the title doesn't mean it was filmed there (we found another country's landmark tagged as the destination) |

**Bandwidth-saving screening (hard rule, decision-maker 2026-10-22, every channel, every footage source)**: look at the platform's preview images first, download HD only for clips you will use; **never let ffmpeg / ffprobe read a remote URL**. Why: one episode's screening script frame-sampled 4K originals remotely and opened ~11,000 outbound connections in an hour. Lower concurrency only slows it down; **dedup and caching are what cut the total**.
1. **Preview images first**: Pexels serves `images.pexels.com/videos/<id>/pictures/preview-<n>.jpg` without an API key (~15 KB each, 8–13 spread over the clip); tile the 15% / 50% / 85% ones and check content, location, faces / gore / illegal camera positions.
2. **Each id is fetched once**: cache by id (previews, headers, low-res copy), shared across queries and episodes; frame grabs, previews and transcodes all read the local copy.
3. **Screen at the lowest resolution**: only when previews aren't enough, fetch the 640-wide copy (`pexels.com/download/video/<id>/?w=640` redirects to it); fetch `?w=1920` (1080 for vertical) only for clips you use; **never the 4K original** (fall back to it only when there is no 1920 rendition, then downscale locally).
4. **3 clips per category first**, at most 2 parallel transfers, one retry on failure, never widen the candidate pool automatically.
5. **Before each batch, report** clip count and expected download; default budget 1 GB per batch, counted from curl's received bytes (failures included); stop and report when it would be exceeded.
- Measured on one clip (33991511): three previews ≈ 40 KB, 640 copy 1.8 MB, 1920 copy 18.8 MB, 4K original 72 MB.
6. **Fetch the rendition the render actually needs** (from 2026-10-22): when footage frames are extracted at 1280×720 (vertical cards 486×864) and the film ships at 720p, fetch `?w=1280` (`?w=720` for vertical) for clips you use, not 1920; fall back to 1920 / the original only when that rendition is missing, then downscale locally. Measured (26970448, ~29 s): 1280 copy 27 MB, 1920 copy 48.8 MB.
7. **Fetch only the seconds you use** (from 2026-10-22): Pexels mp4s are mostly fragmented (moov first, then a moof + mdat every few seconds). Shots usually use the first few seconds of a clip ⇒ fetch the first 64 KB with an HTTP Range request, read how many frames and bytes the first fragment holds, then request only as many fragments as the shot needs; finally trim the incomplete tail (the file keeps only whole fragments, so decoding the whole file reports zero errors). If a shot grows later, resume from the end. Only non-fragmented files (moov at the end) are fetched whole; when there is no 1280 rendition and you must fall back to 1920 / the original, still fetch only the seconds you use and downscale locally (in one travel episode a clip fell back to its original and was fetched whole, 61 MB — this rule was added afterwards). Tool: `pxcache.prefix()`; the shot table computes how far into each clip it reaches, and frame extraction checks the local copy covers it. Measured on 26970448: needed 5 s, fetched 7.5 MB of 27 MB, 8.4 s locally complete; the checker first passed a negative control (cut the last complete fragment in half → decodable seconds drop by one fragment and whole-file decoding reports errors).
- Tools: `engine/tools/pxcache.py` is the only network exit (cache + ledger `ledger.jsonl` + budget; its `local()` guard refuses to hand ffmpeg a remote URL). Episode scripts import it and set `PX_CACHE` (cache dir), `PX_SRC_GLOB` (where each episode's HD copies live) and `PX_TAG` (batch-name prefix); `engine/tools/pxledger.py <ledger> <prefix>` prints an episode's totals by batch and by kind. Other sources (Commons, etc.) follow the same five rules: thumbnails first (`iiurlwidth`), cache by file name, download the large image only when used.

## Pitfalls to check
- **Illegal camera positions**: if drones are banned at the destination, don't use high top-down aerials (we found one on Pexels that was clearly a drone shot); the film can't contradict the rules it teaches.
- **Picture must match narration / caption**: verify with the location on the source page; skip what you can't identify. Captions use the year and author from the original title, never our inference.
- **Old photos may be stereograph cards** (two images side by side on a mount): crop the left image with measured ratios; in one Commons scan batch **file names and contents were swapped** — caption from the title printed on the card.
- **People in footage**: public-domain footage is fine, but avoid close-up faces and injury / gore.
- **Third-party copyrighted shots inside public-domain films**: agency videos splice in satellite maps (Google-marked) or other people's photos, often with a **dissolve**, so scene-cut detection (`select='gt(scene,0.3)'`) merges them with the neighbouring shot ⇒ re-check any chosen range with a frame every 3 s (2026-10-11, second live-footage film: an "underwater reef" range hid 10 s of satellite map).
- **Burned-in watermarks / name captions**: CC BY street footage often carries the videographer's name in a corner; agency films carry lower-third name captions ⇒ zoom in and anchor the focus away from it (`fy: 0` crops the bottom); still credit the author; if it can't be cropped, don't use the shot.
- **Pexels search pages are blocked by Cloudflare for curl**: if WebFetch is unavailable too, `fetch` the search page from inside a pexels.com tab via the browser extension and extract `/video/<slug>-<id>/` and `videos.pexels.com/video-files/<id>/…mp4`; download the CDN files per the bandwidth-saving rules above — no remote frame sampling. The page's `"location"` field is usually the uploader's location, **not** where it was shot — always sample frames and look.
- **Pexels download redirect (2026-10-12)**: WebFetch can read the search page for ids; the 302 target of `pexels.com/download/video/<id>/` is the file URL (response headers alone give each rendition's size). ~~Sample remotely, then download~~ has been replaced by the bandwidth-saving rules above (2026-10-22). **Place names in titles can be wrong too**: a clip tagged as a harbour town turned out, from its red turf-roofed houses, to be Tórshavn in the Faroe Islands; caption any clip without a stated location as "illustrative". For the clip used as the hook, try to confirm the country from the uploader's page (a local photographer, a location in the description).
- **Vector sea charts are more flexible than bitmap charts**: for geography, turn public-domain coastlines (Natural Earth 1:10m / 1:50m) or OpenStreetMap coastlines and streets into paths and draw them every frame (sea, shoreline ripples, land, graticule), with the camera pushing and pulling in chart coordinates; no big jpg needed. **Before placing points on an OSM street map, draw a gridded base map** (a line every 200 chart units, numbered) and check against it: harbours and fissures placed from estimated latitude/longitude once sat well off the real coastline.
- **Building the sea from OSM coastlines (2026-10-17)**: the coastline is a set of ways (land on the left); join them into chains, clip each chain to the query box (insert intersection points where it crosses the edge), then close it into a sea polygon by walking the box edge clockwise from the chain's end back to its start; a fragment closed the wrong way gives a "whole box" polygon ⇒ drop any polygon larger than half the box. Render a gridded debug image first to see which side the sea is on.
- **Some harbours sit outside the coastline (2026-10-22)**: OSM's `natural=coastline` cuts straight across Sydney Harbour's heads; the harbour and estuaries are inland water (`natural=water` relations: Sydney Harbour, Middle Harbour, Parramatta River…). Building the sea from the coastline alone draws the harbour as land. Query the `natural=water` relations in the box first (`out tags bb`, a few KB), pick the harbour ones and fetch them with `out geom`; fill outer rings as water, inner rings (islands) back as land, and stroke the patches in the water colour to hide seams.
- **Don't add `-v error` to cut detection**: `select='gt(scene,0.3)',showinfo` reports its hits in showinfo's info-level log, so `ffmpeg -v error` suppresses them and every clip shows "0 cuts" — a false zero. Run a positive control first: two clips butted together at 2 s must yield exactly one cut at 2.00 s (hit in practice on 2026-10-16).
- **A Commons file name is not its content**: a file titled "Map of the Straits Settlements and Federated Malay States 1907" opened as an album photo of a house (2026-10-16). Tile downloaded images into one contact sheet and look at it before they go into the page and captions.
- **One camera position per shot**: run scene-cut detection on a source before choosing ranges; a shot's "in point + duration × speed" must not cross a cut (or the next camera angle flashes in); if the source is too short, slow it down or pick another clip.

## Getting it into the page (deterministic per frame)
1. **One shot table** (a js file shared by the page and the extraction script): per live shot — clip key, in-point, speed, zoom start/end, focal point, overlays; times anchored to narration sentences.
2. **Extraction script** writes only the needed span to `frames/<shot>/%05d.jpg` (1920×1080, `-q:v 3`; vertical sources take a horizontal band with `crop=iw:iw*9/16:0:(ih-iw*9/16)*cy`; light unified grade `eq=contrast=1.04:saturation=1.06`; `tpad` freezes and warns if the source is too short); unchanged shots are skipped. ~10k frames ≈ 2.4 GB.
3. **The page references frames with SVG `<image>`**, zooms via transforms (sub-pixel smooth). Tested: an `<image>` rebuilt every frame never screenshots blank; prove the checker first with a positive control ("no image → must report blank everywhere") — our first checker measured all-black because of an unquoted SVG attribute, only the positive control caught it.
4. Small frames inside the animation (old film, old video) are extracted at native size and framed with sprocket holes or a white print border.

## Page build
Scene code can live in separate files, but **the engine's `fonts` only scans the page HTML**: on-screen text inside external js is missed and silently falls back. Add a build step that inlines the scene scripts into the page, then run `fonts`.

## Music (when the computer must stay silent)
Without listening, read the loudness curve: `ffmpeg -af ebur128`, one M value every 10 s; pick steady, quiet tracks under narration, put a track's swell on the film's turning point; skip tracks with long near-silent stretches. Normalize each track to the same loudness with `loudnorm`, then crossfade; the total must be **longer than the film** (the mix loops background music, so a short bed restarts at the end).
