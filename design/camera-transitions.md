# 运镜与转场库

目的:运镜、转场、节奏都要**有参考、有数字、有出处**,不凭感觉做。一开始做不到参考的水平没关系,但每个参数都要知道是从哪来的、离参考差多少。

## 规矩
本库的参数都是**默认值**(见 ../principles.md「规矩的三种分量」):是有参考支撑的起点,不是上限。模型能做出更好的运镜和转场就做,写清参考或理由,交付时和库里的默认做法并排比一次;确实更好就回来更新本库。

1. 分镜的衔接表(../transitions.md)里,每个转场写**本库的 id + 参数**,作为起点;要用库外的做法,写清参考来源或理由(不需要先入库)。用过、证明好,再补进库。
2. 每个数字标出处:
   - 【实测】我们按下方方法从参考视频或自己的成片逐帧量出来的(写明片名、日期)
   - 【一手】官方文档 / 作者原话 / 标准
   - 【我们】我们成片里实际用的值
   - 【默认值】有人这样建议、但找不到一手出处也量不到——可以用,拿不准时取写明的保守值
   - 【待测】暂定值,还没有参考支撑——必须在下一次用到前量一次;真测不了就写进「测不了的」,说清原因和量法
3. 交付前用同一套方法量自己的成片(镜头长度、转场时长、静止占比),和参考放一起对比,差距写进验收。

## 拆解一段参考视频(我们的量法)
工具:`../engine/tools/measure_film.py`(整片)、`engine/vc/measure-tx.mjs`(单个转场);步骤:
1. **物理参数**:ffprobe 拿帧率、时长;拿原始最高码率文件,不要录屏。帧号是公共语言。
2. **全貌**:4fps 接触表(标秒)+ 每段关键帧总览。
3. **找转场**:缩到 192×108 灰度算相邻帧平均差,突然变大的地方就是换画面(判法与阈值见 `measure_film.py`)。起点间隔若是常数的整数倍 ⇒ 有节拍网格。
4. **看机制**:每个转场从起点前 2 帧起、每 2 帧一格、取 0.5s,铺 15 格接触表——机制只能从这里看清。
5. **镜内运动**:每段静止区间逐像素取最大帧差做热图,报运动面积占比。没做这一步,做出来就是「图片之间的转场」。
6. **相机缓动**:取相机运动段的位移曲线,拟合缓动(sineInOut / cubic-bezier / 弹簧)。

量完写进下面的表,标【实测】和来源片名。

**量自己的整片**用 `../engine/tools/measure_film.py`(上面第 3、5 步的整片版,流式、不出接触表):静止占比、画面更新间隔、整屏换画面、相邻帧跳变,结果写进下面「我们自己的成片实测」。要看转场机制或拟合缓动,仍按上面第 4、6 步截窗口单独做。

### 共享组件里的四种转场(2026-10-07 实测)
代码:`kit.transition(id, t, t0, A, B, 参数)`(`engine/vc/vc.js`),演示页 `engine/vc/transitions.html`,量法 `node engine/vc/measure-tx.mjs <画风>`。
量法:逐帧(30fps)算「进度 = 到 A 的距离 ÷(到 A + 到 B)」(像素灰度差均值),读 5–95% 用时、到 50% 的时刻(从转场起点算)、相邻帧最大跳变。
**阳性对照**:线性 0.35s 淡化,理论 5–95% = 0.315s、50% = 0.175s;实测 0.30s / 0.20s,三种画风一致,误差在 1 帧(0.033s)内 ⇒ 量法可信。

| id | 设计 | 实测 5–95% | 50% 时刻 | 相邻帧最大跳变 | 说明 |
|---|---|---|---|---|---|
| slide-push | 0.5s cubic-bezier(.7,0,.2,1) | 0.47s | 0.33s(慢起快收,后半程走完) | 19–21 | 和设计 0.5s 一致 |
| blur-push | 0.55s CSS ease | 0.47–0.50s | 0.13–0.17s(新画面很早就能看清) | 1–3 | 和设计 0.55s 一致;软转场,跳变远低于硬切 |
| zoom-through | 1.2s smooth,zoom = Z^e | 1.07–1.10s | 0.87–1.0s(指数推近,大部分变化在后段) | 3–17(开口与底色反差越大越高) | 1.2s 是我们的选择,N10 用过 |
| morph | 0.9s smooth | 0.57–0.67s | 0.57–0.6s | 2 | smooth 缓动;旧元素前 45% 退、新元素后 45% 进,中间只有形状在变 |

三种画风(纸面拟物、科技深色、卡通界面)各量一遍,数字差别都在 1–2 帧内,上表写区间。
| fill-zoom | 0.7s:前 55% expoIn 放大到 30 倍,后 45% 新画面 1.25 → 1 expoOut | 0.23s | 0.33s(变化集中在冲进去的最后一段) | 35 | 跳变偏高,冲击感强 |
| bands | 0.5s expoInOut,三条错开 12% | 0.40s | 0.33s | **112** | **跳变很高**:整屏亮色带扫过非常刺激,一期少用,只给最快的段落切换 |
(fill-zoom、bands 在动态文字画风下量,阳性对照同批 0.30s 通过,2026-10-07。)
用法要点:zoom-through 的开口是圆、画面是矩形,新画面的底子会往外铺三屏;morph 时 A、B 两个镜头都**不画**那个形变的对象,由参数 `from / to`(路径 + 颜色)画;两镜共用的底子要放在外面,别让它跟着淡出淡入(否则中途会露黑)。

### 测不了的(2026-10-07)
- **人做的成片里的淡化时长、文明系列迷雾翻开**:YouTube 下载要登录(yt-dlp 报「Sign in to confirm you're not a bot」),B 站返回 412,游戏录像手头没有。
  量法已备好:拿到视频文件后跑 `uv run engine/tools/measure_fades.py 片子.mp4`。它把每次换画面拟合成「前帧与后帧的混合」,残差小就算淡化,报 5–95% 用时和缓动形状(中段斜率比:线性 ≈ 1,smooth ≈ 1.5–1.9)。
  阳性对照已过:A6 测出 28 次淡化,中位 0.333s(设计 0.35s 线性,理论 0.315s),中段斜率比 1.02(= 线性)。
  要补就请决策者给一两部参考片的文件(3Blue1Brown、Kurzgesagt、TED-Ed 各一部即可),或同意用浏览器 cookies 下载。

## 我们自己的成片实测(2026-10-07)
量的是营养 N9(看板墙,232s)和 AI A6(纸面,407s),命令见 `../engine/tools/measure_film.py`。只量画面区(上 82%,去掉一直在走的字幕和进度条)。参考片的同口径数字还没有,等我们自己量了补一列(还没量)。

| 指标 | N9 | A6 |
|---|---|---|
| 0.5s 内完全不动的时段占比 | **17.8%** | **61.4%** |
| 相邻帧完全静止占比 | 75% | 83% |
| 完全不动 ≥3s 的段数 / 最长一段 | 1 段 / 9.7s(13.2s 处) | **35 段** / 9.4s(336.7s 处) |
| 画面更新(0.4s 内 >1% 画面变化)间隔中位 | 1.7s(每分钟 30 次) | 3.2s(每分钟 14.5 次) |
| 画面更新最长空档 / 超过 5s 的空档数 | 10.5s / 3 个 | 14.4s / **24 个** |
| 换一个镜头 / 场景配几句话 | 中位 5 句(一面墙) | 中位 4 句(一场) |
| 镜头 / 场景时长中位 | 15.0s | 13.3s |
| 换镜手法 | 12 次全是同一种横移,0.85s cubicInOut,峰速 224 px/帧 | 27 次全是 0.35s 线性交叉淡化,零运镜 |
| 相邻帧跳变(平均灰度差最大值) | 28.1,都在横移峰值;无硬切 | 5.4;无硬切 |

**看出来的 3 个问题**(只凭我们自己的数据和看片)
1. **画面停住太多(A6 尤其)。** A6 有六成时间 0.5s 内一动不动,完全不动 ≥3s 的有 35 段;N9 靠每面墙的慢推压到 17.8%,但相邻帧仍有 75% 完全一样。两期都是「长镜头 + 入场后定住」,看着像翻幻灯片。
2. **换镜太慢,一个镜头装太多句话。** 每墙 / 每场中位 4–5 句、13–15s;A6 场内中位 3.2s 才变一次,24 处空档超过 5s,最长 14.4s——观众在这些地方只能听。
3. **转场单一。** N9 的 12 次换墙是同一个横移,0.85s 走一整屏、没有运动模糊,偏急;A6 的 27 次换场全是线性淡化,而本库写的是「fade 只在章节大切换,不当默认」,A6 还一次运镜都没有。

**这次测不准、没写进表的**
- N9 横移的**缓动形状**:相位相关量位移时,墙面网格是周期纹理会混叠,12 次里总位移只量出 1100–1600px(应为 1920),四种缓动的拟合残差拉不开。缓动以源码(cubicInOut)为准,只采信峰速。要量准得换方法(比如追踪墙上的单个元素)。
- A6 有 3 次换场没被「整屏变化 >15%」检出(111.6 / 242.2 / 367.4s):已看画面,是纯文字页换纯文字页,只有 7–8% 像素变了。不是检测器坏,是这三次换场本身变化小;镜头时长按源码的场景表算。

## 我们的差距(下一步)
- 共享组件里已有 morph、zoom-through、fill-zoom、bands、slide-push、blur-push(演示已量);N10 正片用过 morph、zoom-through、slide-push、blur-push、cut、flip、pan。
